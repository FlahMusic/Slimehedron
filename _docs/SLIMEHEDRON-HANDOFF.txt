3. KEY DECISIONS, WITH REASONS
================================================================

Rust owns the physics, not the webview.
  The tank IS the sequencer, not decoration. A DAW can close the
  plugin window while the music keeps playing, and the host owns the
  clock.

GUI = webview (wxp), not a native Rust toolkit.
  The UI is already HTML/CSS/canvas crayon art. egui/iced/vizia would
  mean redrawing the entire app by hand.

CLAP first, VST3 via clap-wrapper.
  CLAP is MIT and the native Rust target. clap-wrapper gives
  VST3/AU/AAX for free.

Three crates, and slimehedron-core has ZERO dependencies.
  wxp is 0.1.0-alpha.x and WRAC states it is "not a general-purpose
  framework" with no API compatibility. If that bet goes bad, only
  the wrapper gets thrown away. Core also compiles to WASM, so the
  website can eventually run the same engine instead of two that
  drift apart.

MIDI IN IS REQUIRED (settled 2026-10-14).
  The chord follower already exists in the web app: manualRoot,
  manualActive, noteManual, noteFeed, pcToNearestDeg. In the plugin
  the player improvises chords on a controller, the follower reads
  the root, and THE BAND TRANSPOSES TO MATCH so the accompaniment
  stays harmonic under their playing. This is the headline feature,
  not a side effect.

MIDI OUT PER CHANNEL IS REQUIRED.
  Every band part (bass, comp, drums, melody) must be outputtable
  live as raw MIDI on its own channel, so it can be recorded,
  re-voiced or edited in the DAW.

WINDOWS ONLY FOR NOW (settled 2026-10-14).
  There is no Mac here to build or sign on. macOS is the last step,
  not a parallel one. Nothing in the plan may assume a Mac.

Everything in cents, not semitones.
  Five of the 25 scales are microtonal (two maqams, neutral7,
  slendro, 19-EDO). A semitone-based table cannot hold them.

Seeded RNG instead of Math.random().
  The audio thread must not allocate or lock, and a test that cannot
  reproduce a note proves nothing.

LICENSING IS CLEAR
  VST3 SDK relicensed MIT by Steinberg (Oct 2025, SDK 3.8).
  CLAP MIT. WRAC/wxp MIT. nice-plug ISC.
  No conflict with Slimehedron's GPL-3.0-or-later.

REJECTED STACKS
  nih-plug   -- maintenance mode per its own README
  nice-plug  -- active ISC fork on Codeberg, but README says
                experimental, and its egui/iced/vizia GUIs cannot
                carry the look
  JUCE / C++ -- full rewrite

Voice::trigger -- the ported playSynth (verbatim)
----------------------------------------------------------------

pub fn trigger(&mut self, freq: f32, vel: f32, imp: f32, firm: bool, s: VoiceSettings, rng: &mut Rng) {
    let dud = !firm && rng.next_f32() < 0.05;      // 1-in-20 quiet drop; rain texture
    let ej = 0.85 + rng.next_f32() * 0.3;           // envelope jitter
    let shorten = 1.15 - imp * 0.4;                 // harder hits decay quicker
    let peak = (vel/127.0) * 0.42 * (if dud {0.16} else {1.0}) * (1.0 - imp*0.18);
    let detune = (rng.next_f32() * 8.0 - 4.0) / 100.0;  // +/-4 cents
    self.target_hz = freq * 2f32.powf(detune / 12.0);
    // pitch settles from freq*1.02 -> freq over 40ms
    // filter sweeps cut_hz(cut+fenv) -> cut_hz(cut) over A+D
}

`firm` means a PERSON did this on purpose -- a firm note can NEVER
dud. One test runs 200 seeds to prove it. A separate test runs 400
seeds to prove a bouncing ball still CAN dud, or the rain model is
gone.


----------------------------------------------------------------
The envelope is not a textbook ADSR
----------------------------------------------------------------

Linear ramp to peak, linear down to sustain, a caller-supplied HOLD,
then exponential release. The hold is a bug fix: it used to be a flat
0.05s, which made a whole note and a quarter note sound identical and
left the note-duration lesson teaching nothing by ear.

#[test]
fn hold_actually_changes_the_length() {
    let short = run(AdsrSettings { hold: 0.05, ..Default::default() }).len();
    let long  = run(AdsrSettings { hold: 1.0,  ..Default::default() }).len();
    let diff = long as f32 - short as f32;
    assert!((diff - 0.95 * SR).abs() < SR * 0.05);
}

The biquad caps Q at 12 -- the web app's "kid-safe: can never scream
or squeal". That cap is a product decision and came along on purpose.

pub fn cut_hz(cut: f32) -> f32 { 60.0 * (18_000.0f32 / 60.0).powf(cut.clamp(0.0, 1.0)) }

TRAPS THAT COST WHOLE SESSIONS -- DO NOT REPEAT

  - offsetParent === null is NOT a visibility test. It is null for
    every position:fixed element. This mistake was made twice in one
    session.
  - getBoundingClientRect inside a closed <details> is NOT zero. Use checkVisibility().
  - flex:1 cannot take space back (default basis auto, and a flex
    item will not shrink below its content). Use flex:1 1 0 with
    min-width:0.
  - Dev suites go stale and will silently guard the exact behaviour
    you just fixed. One asserted "studio still starts jamming on its
    own, by design" -- the bug Flah had filed.
  - dev-goolook's ruler was broken three separate ways and read 0%
    change on deliberate sabotage. Sabotage-test your measuring
    instruments before trusting them.
  - `pkill -f chromium` inside a bash command whose own text contains
    "chromium" kills that shell (and any background runs). Put loops in a
    script file.
  - `pkill -f run.sh` kills your own shell too (its text contains run.sh). Use pkill -f 'run[.]sh g2'.
  - Don't run ad-hoc Playwright scripts while a run.sh batch is going: run.sh pkills chromium between suites.
  - Before blaming your code for a timing failure, run the same suite on the
    previous commit as a control. The container speed changes between sessions.
  - A pkill whose pattern text appears in its own command line kills that shell (exit 144).
    Same for `pkill -f "http.server 8766"`.
  - The app moves some controls BY ITSELF (slime MODS sliders, dlyTop, key travel, random shape).
    Anything that compares snapshots over time (undo, tests) must leave those out.
  - Stacking Playwright runs exhausts the container. Start the server
    with (setsid python3 -m http.server 8765 >/tmp/srv.log 2>&1 &)
    and pkill -f chromium between batches.
  - The studio coach key is 'slimehedron-coach-studio' (play is 'slimehedron-coach'). A suite that only sets
    the play key gets a studio hint that scrolls the side panel.
  - NEVER put a `// comment` in the middle of a one-line statement: it comments out the rest of the line.
    Happened 4+ times in the 2026-10-26 pass (voice leading, renderer try{}, the splash loop, a test). Use /* */.
  - A syntax error in tank3d.js fails SILENTLY: GL never loads and the canvas fallback draws instead. Check
    with `node --check` on a .mjs copy after every edit.
  - Wormholes glide during the first 60% of each beat. A test that pins beatNow must pin it late in a beat
    (x.8) or the holes are mid-move, and must keep it pinned through screenshots (a queued rAF fires once more).
