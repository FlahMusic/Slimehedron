Accessibility

Slimehedron is a free music toy for children that runs in a browser tab.

Target standard: WCAG 2.2 Level AA. That is the bar set by the US ADA Title II web rule and by the UK public sector accessibility regulations. We are not fully there. This page says which parts we test, which parts pass, and which parts do not.

Open Slimehedron

What is tested automatically

The repository contains an accessibility test suite, dev-a11y.js, which drives a real browser against the real app. It is public and you can run it yourself. As of 23 September 2026 it runs 33 checks and all 33 pass.

Here is what those checks actually verify. Nothing outside this list is machine-tested, so nothing outside it is claimed as conformant.

CheckedWhat it provesResult
Touch target size
SC 2.5.5 / 2.5.8		 Every visible button, link, select, input and label in play, studio, learn and the front page is at least 44×44 CSS pixels. Run at 390px and again at 375px wide. Two documented exemptions: links inside a sentence, and the step-sequencer grid, both of which SC 2.5.8 permits. pass
Mute is a real button
SC 4.1.2		 The speaker icon is a <button>, it toggles aria-pressed, it changes its own accessible name to “unmute”, and it genuinely silences the audio rather than just looking muted. pass
Mute is not colour alone
SC 1.4.1		 The muted state is carried by a shape: a slash appears and the sound waves disappear. The test measures the opacity of both, it does not take the CSS on trust. pass
Mute is reachable In play, in studio, and inside a lesson, the mute button is on screen, is 44px, and answers a tap at its own centre rather than sitting under something else. A child in a lesson can always turn the sound down. pass
Lit sequencer steps are not colour alone
SC 1.4.1		 An active step in the step sequencer carries a dot as well as a fill. pass
Colour-blind mode works The switch is on the front page, in a bottom corner, fully on screen, 44px, and not overlapping anything. Ticking it turns the mode on, saves the choice for next time, and repaints the slime tank itself — not just the menus around it. pass
Colour-blind mode is measured, not assumed The test simulates deuteranopia (Machado 2009, in linear RGB) and measures the Lab distance between the palette's two known collisions. Pink against mint goes from ΔE 4.8 to 15.0; lavender against sky from 5.0 to 23.1. Both clear ΔE 10, the point where a pair is reliably tellable apart. pass
Layout congruence
SC 3.2.3		 The transport controls sit at the same horizontal position in play and in studio, so a control does not move when a child changes room. Measured drift: 0–1px. pass

What is built in but not machine-tested

These are in the code and we believe they work. They are not covered by the automated suite, so treat them as claims to verify rather than as verified claims.

  • Pinch zoom is not blocked. The page allows scaling up to 5× (SC 1.4.4).
  • Reduced motion is respected in 13 places in the stylesheet. Card transitions, hover transforms and the lesson-complete animation stop when the operating system asks for less motion (SC 2.3.3).
  • Visible focus. Ten :focus-visible rules draw a 3px outline with an offset.
  • Accessible names. Around 40 aria-label attributes across the app and the lesson engine.
  • Lesson instructions are read aloud using the browser's own speech synthesis, so a child who cannot read yet can start a lesson alone. There is a speaker button on every lesson to turn it off.
  • No fail state. A wrong answer repeats the question. No timer, no streak, no score, nothing to lose.
  • Colour is systematic. Every scale degree keeps one colour in every lesson and every key, so colour is a consistent label rather than the only channel of meaning.

What is not met

Named plainly, because a vague accessibility page is worse than none.

It is an audio-first app

The whole point is listening. Pitch, rhythm, interval and tonic are taught by ear. A deaf child cannot use the lessons for their intended purpose, and no caption or transcript fixes that, because the sound is the content rather than a delivery of it. The visual side — the tank, the keyboard, the sequencer, the notation — remains usable and is genuinely fun on its own, but it is not the lesson. We say this straight rather than claiming an equivalent experience that does not exist.

The slime tank is visual physics

Balls bounce around a tank and strike notes. That is a visual, continuous, non-verbal thing. It has no text equivalent and no screen-reader description. In play mode this is most of the screen.

Screen reader support is partial

Controls have accessible names and the mute button reports its state correctly. But there are no aria-live regions, so a change the app announces visually — a correct answer, a mode change, a toast message — is not announced to a screen reader. There is no skip link. We have not run a full screen-reader pass with NVDA, JAWS or VoiceOver, and so we make no conformance claim for SC 4.1.3 or for the 1.3.x set.

Colour contrast is not automatically tested

The suite tests colour-blind separation, which is a different thing from contrast ratio. SC 1.4.3 and 1.4.11 are not machine-verified across the app. We have not audited every text-on-background pair.

Keyboard-only operation is incomplete

There are keyboard shortcuts, and controls take focus. We have not verified that every path through the app can be completed with a keyboard alone, so SC 2.1.1 is not claimed.

Headphones or a speaker are required

It is all sound. There is no silent mode of use.

Reporting a problem

If something here is wrong, or you hit a barrier this page does not mention, tell us and be specific about the device and browser:

  • Email flahobino@gmail.com
  • Or open an issue at github.com/FlahMusic/Slimehedron/issues

We aim to reply within five working days. The app is free and maintained by one person, so a fix takes as long as it takes, but you will get a straight answer about whether it is going to be fixed.
